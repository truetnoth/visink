`foundation.json` — точные ID созданных коллекций, переменных, стилей и контейнера компонентов. `start-screen-result.json` — все ID узлов успешной записи первого экрана. `state.json` — файл, сессия и точка продолжения.

`build-screen.js` — рабочий, ещё не прошедший визуальную проверку генератор для `use_figma`. Перед ним задаются `F` (foundation.json), `data` (JSON экрана), `theme` (`Light`/`Dark`), `screenName` и `screenIndex` (0–15). Он создаёт редактируемый текст, SVG, auto-layout и экземпляры общих компонентов. Не запускать повторно на уже созданном экране без инвентаризации: создание корневого фрейма не идемпотентно.

## Продолжение после восстановления доступа

1. Прочитать сохранённые ID и проверить существующие узлы, в том числе отсутствие остатков неуспешных попыток. Не удалять референсы пользователя.
2. Проверить стартовый экран скриншотом Figma и исправить геометрию генератора, если потребуется.
3. Основной шрифт приложения на macOS — SF Pro, доступен в Figma. Menlo для кода недоступен; временная замена в генераторе — JetBrains Mono. Вопрос о замене задан пользователю, явного ответа на момент сохранения нет. До закрытия итерации согласовать замену или подключить Menlo и создать общий моноширинный стиль.
4. Перенести остальные экраны последовательными пакетами. Проверить стрелки, порядок наложения, размеры текста и обрезку содержимого; не использовать целые скриншоты вместо слоёв.
5. Упорядочить и дать понятные имена компонентам, добавить необходимые текстовые свойства и варианты. Сейчас технические имена компонентов содержат хэш для повторного использования.
6. Проверить количество редактируемых текстов, экземпляров и векторов; проверить использование токенов и шрифтов. Визуально сверить с PNG-эталонами. Удалить только временный захват `17:2` после успешной сверки.
7. Обновить каталог ссылок и PLAN.md. Только после этих проверок отмечать итерацию выполненной.

Это комплект для продолжения работы, а не заявка о готовности всех макетов.
