# Visink 0.7.0

![Visink](packages/app/src/assets/visink-logo.png)

Визуальный редактор диалогов в духе articy: реплики — карточки на холсте, развилки — стрелки, на выходе — обычные `.ink`-файлы. ТЗ — в `ТЗ визуальный редактор ink в духе articy.md`.

## Запуск

```sh
npm install
npm run dev      # http://localhost:5173, открывать в Chrome или Edge
npm test         # компилятор и проверки, ink компилируется inkjs
npm run demo     # пересоздать examples/demo.visink из тестовой фикстуры
```

В приложении: «Открыть…» → папка `examples/demo.visink` или «Новый проект…» → пустая папка. Ctrl+S сохраняет проект и, если нет ошибок, пишет сборку в `build/narrative` внутри проекта (или во внешнюю папку — кнопка «Собирать во внешнюю папку…» в свойствах проекта, например прямо в проект Godot).

## Настольное приложение (Tauri)

```sh
npm run desktop:dev     # окно приложения с горячей перезагрузкой (сам поднимает vite на 5173)
npm run desktop:build   # .app и .dmg в packages/desktop/src-tauri/target/release/bundle/
```

Нужен Rust (`rustup`). В приложении папки выбираются системным диалогом, последний проект открывается при запуске, внешняя папка сборки запоминается для каждого проекта. Файлы читает и пишет Rust (`packages/desktop/src-tauri/src/lib.rs`), только внутри выбранной папки.

## Рабочие режимы

- **Канвас** — один главный холст проекта соответствует `main.ink`. Каждая именованная вложенность одновременно является карточкой-контейнером, папкой в дереве и отдельным knot в собственном `.ink`-файле. В интерфейсе пины видны внутри вложенностей. Сборка использует технические границы корневого канваса. Ветки через «Выход» продолжают связи карточки-контейнера в родителе, а корневой «Выход» завершает поток. Двойной щелчок по шапке вложенности редактирует её имя, шапку можно перетаскивать; одинарный щелчок по телу редактирует сохраняемое описание, двойной открывает содержимое. Breadcrumbs сверху возвращают наверх.
- **Логика** — глобальные переменные и функции, а также именованные наборы переменных: например, `quest.first_met`. Переменные можно переносить между глобальной областью и наборами. Существующие LIST доступны для редактирования в разделе совместимости; создание новых LIST убрано.
- **Сущности** — персонажи, предметы, локации и навыки со своими переменными и функциями. Стабильный ID не меняется; техническое имя можно редактировать. Например, `hero.trust` экспортируется в Ink как `hero__trust`. Переименование обновляет ссылки в логике проекта; обращения из внешнего игрового кода нужно обновить отдельно.
- **Тестирование** — запуск фактической сборки через inkjs, выбор файла или точки входа, продолжение, варианты выбора, просмотр тегов и переменных, переход к текущей карточке. Для EXTERNAL в прогоне используется запасное тело функции.

Дерево проекта слева показывает глобальные переменные, наборы, сущности и главный канвас со всеми уровнями карточек-вложенностей и групп. Обычные карточки не содержат дочерних строк; у вложенности показано только содержимое её холста. Выделение синхронизировано с холстом; выбор вложенной карточки раскрывает путь к ней. Подробности свёрнуты до раскрытия соответствующей ветки. Постоянной правой колонки нет: карточки редактируются прямо на холсте, свойства стрелок и проекта открываются контекстными диалогами. Щелчок по входному пину открывает компактное условие, двойной щелчок по выходному — действие. Щелчок на выходной пин открывает выбор 1–4 и каскадное меню карточек; оба выхода условия поддерживают несколько связей. Подсказки выражений показываются поверх карточек и окна пина, поддерживают мышь и клавиатуру.

## Текст и входы карточек

При редактировании текста на канвасе панель форматирования появляется сверху. Выделенный фрагмент можно сделать жирным, курсивным, подчёркнутым, зачёркнутым или моноширинным, изменить размер, заключить в кавычки и очистить оформление. Оформление хранится в проекте, а Ink получает обычный текст.

В контекстном меню карточки откройте «Входы», добавьте `input_1` и задайте значение по умолчанию. Дважды щёлкните по входящей стрелке и укажите выражение в аргументе, например `RANDOM(1, 20)`. В реплике или варианте игрока напишите `Выпало {input_1}`. При наборе внутри скобок редактор подсказывает локальные входы, переменные и функции Ink.

Входные значения принадлежат карточке. При каждом новом входе пустые аргументы получают значения по умолчанию. Для вариантов игрока выражения вычисляются перед показом меню, и выбранная реплика получает те же значения. Действия выбранной связи выполняются после выбора. Вход вложенности доступен для её собственного условия и действия. Карточки внутри вложенности получают свои значения по своим входящим связям.

## Как игра запускает диалог

- Главный холст — knot `main`. Его маршрут из технической карточки «Вход» используется при запуске `main.ink`. Контекстное действие «Сделать началом канваса» на корневой карточке переназначает этот маршрут.
- Игра запускает диалог так: `ChoosePathString("dean")` — с начала файла.
- **Дополнительная точка входа** (свойства карточки) — если диалог иногда начинается не с начала, например со второй встречи: `ChoosePathString("dean.entry_second_meeting")`.
- **Переход** — карточка jump ведёт к файлу, точке входа или любой карточке по адресу `dean.c2`, включая реплики, хабы и содержимое вложенностей. Цель можно выбрать из списка с поиском. Двойной щелчок по текущей цели открывает место перехода.
- **Запуск всей истории** следует маршруту главного «Входа». Старые настройки запуска при миграции превращаются в этот маршрут с сохранением поведения; Godot может по-прежнему использовать прежние адреса из manifest.

## Пакеты

| Пакет | Что делает |
| --- | --- |
| `packages/core` | модель данных, стабильный JSON, загрузка и сохранение проекта через `ProjectFs` |
| `packages/compiler` | холсты → `main.ink`, `globals.ink`, файл на холст, `manifest.json`, карта строк ink ↔ карточек |

| `packages/app` | интерфейс: Vite + React + React Flow + Zustand (undo через zundo) |
| `packages/desktop` | настольное приложение на Tauri 2: окно, системные диалоги, файловые команды на Rust |

## Сборка для движка

- Узел ink = холст, стежок = id карточки. Все холсты экспортируются плоско по стабильным техническим ID. Старые адреса `dean.c2` и `dean.entry_first_meeting`, включая карточки внутри вложенностей, сохраняются через совместимые стежки; текстовые ID также сохраняют прежний корневой файл.
- Ветка, дошедшая до «Выхода», возвращается к контейнеру в родителе; на главном холсте заканчивается `-> DONE`. Явные переходы/jump, карточки «ink» с `-> END` / `->->` и обычные окончания веток не смешиваются.
- В проекте один файл `canvases/main.canvas.json` с рекурсивными холстами. В сборке `<id>.ink` для каждого холста; старые проекты с папками-категориями и прежними карточками «Вход»/«Конец» переводятся автоматически при открытии. Старые организационные папки сохраняются для карточек верхнего уровня и не меняют пути Ink-файлов.
- У каждой строки теги `id: холст.карточка`, `speaker: ent_…`, по желанию `emotion:`, `dir:` и свои теги.
- `manifest.json` — холсты с точками входа, персонажи (имя, цвет, портрет) и тексты всех строк по id.
- Компилировать нужно только `main.ink` — остальные файлы подключены через `INCLUDE`.

## Совместимость проектов

При первом сохранении проекта прежнего формата исходные JSON-файлы сохраняются в `.backups/pre-v4/` (для более старых форматов остаются `.backups/pre-v3/` и `.backups/pre-v2/`), затем записывается формат 4 с главным холстом. При ошибке копирования сохранение останавливается. Если удаление старых файлов прервалось, повторное открытие v4 использует только `main.canvas.json`, а следующее сохранение удаляет сгенерированный остаток. Для возврата к старому редактору восстановите исходные JSON-файлы из соответствующей копии.

## Организация и перетаскивание

- Правый клик по разделу или папке открывает создание файла, сущности, набора или переменной. В файле или вложенности доступны создание карточек и заметок. Уже существующие папки, включая пустые и вложенные, можно переименовывать, удалять и использовать для организации и перетаскивания. Старое текстовое поле «Папка» заменено деревом.
- Для выбора нескольких строк используйте ⌘ на macOS / Ctrl на Windows или Shift для диапазона. Перетащите выбранное в совместимую папку. Нельзя переносить элементы в чужой раздел или папку внутрь себя.
- Переменные и функции можно переносить между глобальной областью и наборами через выпадающий список «Набор»: обращения в проекте обновляются, зависимости перенесённой функции сохраняются. Переменные сущности остаются внутри сущности.
- Перетащите файл или карточку из дерева на **пустую карточку перехода**, чтобы назначить цель. Для выражений используйте автодополнение; отдельные переменные и функции в дереве не показываются.
- Перенос карточек в дереве: цель — главный файл или карточка с вложенным содержимым. Вся выбранная группа перемещается вместе с внутренними связями и вложенностями. При наличии авторских связей с оставшимися карточками перенос запрещён (курсор запрета, без всплывающего сообщения). Связи с техническими границами корректно переходят к границам целевого холста.
- Конфликты ID и точек входа разрешаются добавлением суффикса; переходы внутри проекта обновляются. Перенос — отдельный шаг Undo/Redo. Прежние адреса обновляются относительно фактических исходного и целевого холстов.

Текстовые области реплики редактируются кликом в любом месте блока. Пустой основной текст не имеет плейсхолдера. При вытягивании стрелки на свободный холст новая карточка создаётся в точке отпускания, с учётом привязки к сетке.

macOS-иконка пересобирается командой `swift scripts/make-macos-icon.swift`: исходный рисунок сохраняется, во все размеры `.icns` добавляются прозрачные поля. После изменения иконки нужна новая сборка приложения (`npm run desktop:build`) и перезапуск установленной версии.
