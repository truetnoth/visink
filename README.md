# Visink 0.5

![Visink](packages/app/src/assets/visink-logo.png)

Визуальный редактор диалогов в духе articy: реплики — карточки на холсте, развилки — стрелки, на выходе — обычные `.ink`-файлы. ТЗ — в `ТЗ визуальный редактор ink в духе articy.md`.

## Запуск

```sh
npm install
npm run dev      # http://localhost:5173, открывать в Chrome или Edge
npm test         # компилятор и проверки, ink компилируется inkjs
npm run demo     # пересоздать examples/demo.visink из тестовой фикстуры
```

В приложении: «Открыть…» → папка `examples/demo.visink` или «Новый проект…» → пустая папка. Ctrl+S сохраняет проект и, если нет ошибок, пишет сборку в `build/narrative` внутри проекта (или во внешнюю папку — кнопка «Собирать во внешнюю папку…» в свойствах проекта, например прямо в проект Godot).

## Настольное приложение (Tauri)

```sh
npm run desktop:dev     # окно приложения с горячей перезагрузкой (сам поднимает vite на 5173)
npm run desktop:build   # .app и .dmg в packages/desktop/src-tauri/target/release/bundle/
```

Нужен Rust (`rustup`). В приложении папки выбираются системным диалогом, последний проект открывается при запуске, внешняя папка сборки запоминается для каждого проекта. Файлы читает и пишет Rust (`packages/desktop/src-tauri/src/lib.rs`), только внутри выбранной папки.

## Рабочие режимы

- **Канвас** — карточки, связи и именованные карточки-вложенности. Двойной щелчок по телу открывает содержимое вложенности, по шапке — настройки любой карточки или выделенной группы. Breadcrumbs сверху возвращают наверх. Внутренний поток начинается без отдельной стартовой карточки, а его свободные концы автоматически продолжают выходы родительской вложенности. Всё содержимое копируется вместе с родительской карточкой и компилируется в тот же `.ink`-файл, без отдельных игровых узлов.
- **Логика** — глобальные переменные и функции, а также именованные наборы переменных: например, `quest.first_met`. Переменные можно переносить между глобальной областью и наборами. Существующие LIST доступны для редактирования в разделе совместимости; создание новых LIST убрано.
- **Сущности** — персонажи, предметы, локации и навыки со своими переменными и функциями. Стабильный ID не меняется; техническое имя можно редактировать. Например, `hero.trust` экспортируется в Ink как `hero__trust`. Переименование обновляет ссылки в логике проекта; обращения из внешнего игрового кода нужно обновить отдельно.
- **Тестирование** — запуск фактической сборки через inkjs, выбор файла или точки входа, продолжение, варианты выбора, просмотр тегов и переменных, переход к текущей карточке. Для EXTERNAL в прогоне используется запасное тело функции.

Дерево проекта слева показывает глобальные переменные, наборы, сущности и файлы со всеми карточками, вложенностями, заметками и группами. Обычные карточки не содержат дочерних строк; у вложенности показано только содержимое её холста. Выделение синхронизировано с холстом; выбор вложенной карточки раскрывает путь к ней. Подробности свёрнуты до раскрытия соответствующей ветки. Постоянной правой колонки нет: карточки редактируются прямо на холсте, свойства стрелок и проекта открываются контекстными диалогами. Щелчок по входному пину открывает компактное условие, двойной щелчок по выходному — действие. Щелчок на выходной пин открывает выбор 1–4 и каскадное меню карточек; оба выхода условия поддерживают несколько связей.

## Как игра запускает диалог

- Каждый файл — отдельный диалог: узел ink с именем файла. У файла одно **начало** — карточка с флажком в шапке; новый файл создаётся с первой карточкой-началом, перенести начало — правый щелчок по карточке → «Сделать началом файла».
- Игра запускает диалог так: `ChoosePathString("dean")` — с начала файла.
- **Дополнительная точка входа** (свойства карточки) — если диалог иногда начинается не с начала, например со второй встречи: `ChoosePathString("dean.entry_second_meeting")`.
- **Переход** — карточка jump ведёт к файлу, точке входа или любой карточке по адресу `dean.c2`, включая реплики, хабы и содержимое вложенностей. Цель можно выбрать из списка с поиском.
- **Запуск всей истории** (свойства проекта) — куда переходит `main.ink`; нужен для Inky и прогона всей истории целиком. Godot его не использует.

## Пакеты

| Пакет | Что делает |
| --- | --- |
| `packages/core` | модель данных, стабильный JSON, загрузка и сохранение проекта через `ProjectFs` |
| `packages/compiler` | холсты → `main.ink`, `globals.ink`, файл на холст, `manifest.json`, карта строк ink ↔ карточек |
| `packages/checker` | компиляция inkjs, перенос ошибок на карточки, тупики, недостижимые карточки |
| `packages/app` | интерфейс: Vite + React + React Flow + Zustand (undo через zundo) |
| `packages/desktop` | настольное приложение на Tauri 2: окно, системные диалоги, файловые команды на Rust |

## Сборка для движка

- Узел ink = холст, стежок = id карточки (не меняется никогда). Игра запускает `ChoosePathString("dean")` (с первой карточки холста) или `ChoosePathString("dean.entry_first_meeting")` (карточка с точкой входа `first_meeting`).
- Ветка без стрелок заканчивается `-> DONE`. Конец игры и возврат из туннеля — карточкой «ink» с `-> END` / `->->`.
- Файлы холстов лежат плоско: `canvases/<id>.canvas.json`, в сборке `<id>.ink`. Старые проекты с папками-категориями и карточками «Вход»/«Конец» переводятся автоматически при открытии. Организационные папки сохраняются в проекте и не меняют пути Ink-файлов.
- У каждой строки теги `id: холст.карточка`, `speaker: ent_…`, по желанию `emotion:`, `dir:` и свои теги.
- `manifest.json` — холсты с точками входа, персонажи (имя, цвет, портрет) и тексты всех строк по id.
- Компилировать нужно только `main.ink` — остальные файлы подключены через `INCLUDE`.

## Совместимость проектов

При первом сохранении проекта формата 2 исходные JSON-файлы сохраняются в `.backups/pre-v3/`, затем записывается формат 3 с папками. Для проектов формата 1 резервная копия остаётся в `.backups/pre-v2/`. При ошибке копирования сохранение останавливается. Для возврата к старому редактору восстановите исходные JSON-файлы из соответствующей копии.

## Организация и перетаскивание

- Правый клик по разделу или папке открывает создание папки, файла, сущности, набора или переменной. В файле или вложенности доступны создание карточек и заметок. Папки могут быть пустыми и вложенными; их можно переименовать, пустые — удалить. Старое текстовое поле «Папка» заменено деревом.
- Для выбора нескольких строк используйте ⌘ на macOS / Ctrl на Windows или Shift для диапазона. Перетащите выбранное в совместимую папку. Нельзя переносить элементы в чужой раздел или папку внутрь себя.
- Переменные и функции можно переносить между глобальной областью и наборами через выпадающий список «Набор»: обращения в проекте обновляются, зависимости перенесённой функции сохраняются. Переменные сущности остаются внутри сущности.
- Перетащите файл или карточку из дерева на **пустую карточку перехода**, чтобы назначить цель. Для выражений используйте автодополнение; отдельные переменные и функции в дереве не показываются.
- Перенос карточек в дереве: цель — файл или карточка с вложенным содержимым. Вся выбранная группа перемещается вместе с внутренними связями и вложенностями. При наличии связей с оставшимися карточками перенос запрещён (курсор запрета, без всплывающего сообщения). Начало исходного файла сначала нужно переназначить.
- Конфликты ID и точек входа разрешаются добавлением суффикса; переходы внутри проекта обновляются. Перенос — отдельный шаг Undo/Redo. Обращения из внешнего игрового кода к перемещённым точкам входа нужно обновить отдельно.

Текстовые области реплики редактируются кликом в любом месте блока. Пустой основной текст не имеет плейсхолдера. При вытягивании стрелки на свободный холст новая карточка создаётся в точке отпускания, с учётом привязки к сетке.

macOS-иконка пересобирается командой `swift scripts/make-macos-icon.swift`: исходный рисунок сохраняется, во все размеры `.icns` добавляются прозрачные поля. После изменения иконки нужна новая сборка приложения (`npm run desktop:build`) и перезапуск установленной версии.
